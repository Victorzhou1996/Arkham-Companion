# Arkham Horror 新版本产物流程

本流程用于每次正式发布新版本。未经明确确认，不得跳过备份、验证或把 `unkai` 的版本继续同步到 `online`。

## 1. 发布前冻结与记录

1. 确认本次源代码、中文文本、卡图和 Build 数据版本。
2. 记录 Git 分支、提交号、未提交修改和版本日期。
3. 创建版本更新日志，列出前端、后端、卡牌规则、汉化、卡图和 Companion 的变化。
4. 运行前置检查；检查失败时停止发布，不生成可分发产物。

## 2. 必须生成的产物

### macOS 本地版

- 独立运行，不依赖远端服务器。
- 包含 macOS arm64 后端、前端、Build、数据库运行环境和完整中文卡图库。
- 产出完整压缩包，并在需要正式分发时生成 DMG/App 安装包。
- 验证首页、建局、读取存档、Build、中文卡图和关闭后再次启动。

### Windows 本地版

- 独立运行，不依赖远端服务器。
- 包含 Windows 启动程序、Linux/WSL 后端运行方案、前端、Build 和完整中文卡图库。
- 产出可安装或可解压运行包。
- 在干净 Windows 环境验证首次安装、启动、关闭、重启、Build 和存档保留。

### Linux 本地版（服务器/NAS）

- 提供 Linux amd64 后端、前端和部署脚本。
- 配套说明端口、反向代理、数据目录、升级和回滚方法。
- 数据库、配置、卡图和用户存档必须放在版本目录之外，升级不得覆盖。
- 在 Linux 服务器或 NAS 环境验证启动、健康检查、WebSocket、Build 和重启恢复。

### unkai / online 服务器更新包

- 服务器更新包只包含需要替换的前端和 Linux 后端，不包含数据库或用户存档。
- 前端目录统一使用目录 `755`、文件 `644`，确保独立运行服务和公网反向代理都能读取。
- 每台服务器更新前分别备份：数据库、当前后端、当前前端、配置和附加服务。
- 先更新 `unkai` 并完成测试；只有用户明确批准后，才能更新 `online`。
- `online` 必须单独再次备份，不能把 `unkai` 的数据库、存档或配置复制过去。
- 验证登录、存档列表、创建游戏、进入游戏、WebSocket、Build、Bug 列表、中文文本和卡图。

### macOS / Windows Companion

- 生成 macOS Companion 安装包和 Windows Companion 安装包。
- 包含完整中文卡图库、本地图片服务、用户替换目录和服务器网页入口。
- 验证默认浏览器与内置窗口、标签关闭、本地图片优先、缺图回退和卡图替换。
- Companion 不携带服务器数据库，也不改变远端存档同步逻辑。

## 3. 统一产物清单

每个版本目录至少包含：

- macOS 完整本地版。
- Windows 完整本地版。
- Linux 服务器/NAS 部署包。
- unkai/online 增量服务器更新包。
- macOS Companion 安装包。
- Windows Companion 安装包。
- 更新日志。
- 源代码状态记录。
- 所有产物的 SHA-256 校验文件。
- 构建和测试报告。

## 4. 固定发布顺序

1. 生成并验证全部本地产物。
2. 本机验证 macOS 本地版和 Companion。
3. 备份并更新 `unkai`。
4. 完成 `unkai` 冒烟测试，交由用户实际验证。
5. 获得用户明确批准。
6. 单独备份并更新 `online`。
7. 完成 `online` 冒烟测试。
8. 更新 GitHub、README、版本日志和下载链接。

## 5. 回滚要求

- 每次大更新使用独立、带时间戳的备份目录。
- 备份应包含可直接恢复的前端和后端，以及经过验证的数据库逻辑备份。
- 部署失败或健康检查失败时立即恢复上一版本，不继续更新下一台服务器。
- 回滚后再次验证登录、存档、建局和 WebSocket。

## 6. 发布完成标准

只有在所有目标产物存在、SHA-256 一致、测试报告通过、备份可用且目标服务器验证完成后，才将该版本标记为已发布。
