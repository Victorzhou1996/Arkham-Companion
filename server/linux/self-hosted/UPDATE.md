# 更新、备份恢复与回滚

## 更新已有实例

1. 只读确认当前服务、实际应用目录、环境文件、数据目录、端口。不要把本文件的默认值直接套到已有站点。
2. 先停止**对应实例**，用旧版本 `server.sh backup` 生成完整冷备，`tar -tzf` 验证能读取。保留原版本及原配置。
3. 把新包解压到新版本目录，运行 `sha256sum -c SHA256SUMS`；不要覆盖旧目录或把旧 state/logs/密钥复制到新包。
4. 新版本继续读取**同一份外部环境文件和数据目录**。确保新的应用目录归对应服务用户所有，首启会把会话密钥连接到同一外部 secrets 文件。
5. 修改该实例 systemd unit 的 WorkingDirectory/ExecStart 为新目录；先 `systemd-analyze verify`，再 `systemctl daemon-reload`、启动对应服务。不得启用两个使用同一数据库/端口的副本。
6. 验证健康、登录、原存档、Build、卡图、WebSocket、布局，再恢复对外流量。升级过程中已有的兼容迁移沿用原游戏逻辑；不要手工对旧数据库执行 setup.sql。

仅回退前端或相同数据库版本的代码时，停止本实例，将服务目录切回旧版本再启动即可。**不要为回退界面而恢复数据库**，否则会覆盖升级后的玩家进度。

## 在新实例恢复冷备

完整冷备包含物理 PostgreSQL 数据，仅用于相同 CPU 架构和兼容 PostgreSQL 主版本；跨 PostgreSQL 主版本迁移应由管理员使用 `backups/latest.dump` 的逻辑备份恢复，不能直接混用数据目录。

恢复前停止目标实例；验证压缩包成员全部在 `arkham-server-state/` 下，无绝对路径、`..`、符号链接或设备文件。不对正在使用的数据目录解压覆盖。

将备份解压到**全新的空暂存目录**，检查 pgdata/PG_VERSION、secrets 三个文件、卡图和布局文件；权限交给目标服务用户（数据目录 700、密钥 600）。备份中原秘密必须一起恢复，不能新生成数据库密码代替旧密码。

将环境文件 ARKHAM_SERVER_DATA 指向新的恢复目录（目录内容应直接含 pgdata、secrets 等），应用目录使用未启动过的干净副本；原数据目录保留用于回滚。端口和外层代理按目标机器重新核对。启动验证成功后再由管理员决定旧副本保留时间。

`server.sh backup` 不打包 run/ 的临时 PID、Unix socket、日志和机器配置；恢复不会带来旧进程号或旧安装绝对路径。启动脚本会按新数据目录/端口重写 PostgreSQL socket 与内部 nginx 配置。禁止把私钥、邮件令牌或其他服务器秘密夹带进发布包。
